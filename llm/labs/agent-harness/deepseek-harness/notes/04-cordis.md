# Cordis

dsh의 플러그인 구조는 Cordis 위에 얹혀 있다. DeepSeek이 만든 것이 아니라
가져다 쓴 것이므로 따로 정리한다.

## 무엇인가

shigma 가 만든 독립 오픈소스 메타프레임워크. 프레임워크를 만들기 위한 프레임워크다.
이름은 라틴어로 심장을 뜻한다.

특정 용도를 위한 API를 제공하는 대신, 플러그인 체계와 의존성 관리, 자원 생명주기
관리라는 토대만 제공한다. 챗봇 프레임워크 Koishi의 기반으로 4년간 쓰였고 그
생태계에 플러그인이 4천 개 넘게 쌓였다.

dsh에는 `@deepseek-ai/cordis` 4.0.1 로 들어가 있으며 패키지의 author 는 원저자
그대로다. 저장소 안 `vendor/cordis` 에 담아 쓴다.

## 핵심 기능

문서가 내세우는 것은 하나다. 플러그인을 올리고, 내리고, 다시 올릴 때 부작용까지
완전히 정리하는 것이다. 이것이 되기 때문에 실행 중에 구조를 갈아끼울 수 있고,
dsh가 모든 구성 요소를 플러그인으로 둘 수 있다.

README가 밝히는 성질은 네 가지다.

- 명시적 의존성 주입
- 범위가 있는 서비스
- 생명주기가 관리되는 정리
- 설정 파일로 구동하는 적재

구현 수준의 내용은 `06-cordis-internals.md` 에 정리했다.

## 설계 논문

`A Programming Paradigm for Spatiotemporal Composability` 가 v4 재설계를 이끌었다.
동적 합성을 두 축으로 나눈다.

| 축 | 내용 |
| --- | --- |
| 시간적 합성 | 컴포넌트의 효과를 완전히 되돌릴 수 있다 |
| 공간적 합성 | 컴포넌트 사이의 의존을 선언하고 반응적으로 관리한다 |

dsh가 공개된 날 이 논문도 함께 나왔다.

## dsh에서 어떻게 드러나는가

| Cordis 성질 | dsh에서의 결과 |
| --- | --- |
| 범위가 있는 서비스 | 세션마다 플러그인이 격리된다 |
| 생명주기 정리 | 실행 중에 플러그인을 올리고 내릴 수 있다 |
| 의존성 주입 | 행의 순서가 적재 순서를 뜻하지 않는다. 필요한 서비스가 갖춰지면 활성화된다 |

세션 기록과 되돌리기는 Cordis가 아니라 dsh의 세션 플러그인이 담당한다.
`dsh-session-persistence-jsonl` 이 대화를 파일로 남기고,
`dsh-session-checkpoint-policy` 가 모델 요청 전과 도구 부작용 전에 체크포인트를 찍는다.
