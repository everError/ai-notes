# 에이전트 하네스란 무엇인가

## 정의

모델 자체가 아니라 모델을 감싸는 실행 계층이다. 모델은 다음 토큰을 생성할 뿐이므로,
실제 작업을 끝내려면 그 주변에서 다음을 담당하는 구성 요소가 필요하다.

- 대화와 작업 상태를 유지하는 세션 관리
- 도구 정의 노출과 도구 호출 결과 반환
- 파일 시스템, 셸, 샌드박스 등 환경 접근
- 작업이 끝날 때까지 반복하는 에이전트 루프
- 길어진 대화를 잘라내거나 요약하는 컨텍스트 관리

동일한 모델이라도 하네스 설계에 따라 실제 작업 성공률이 크게 달라진다. 모델 성능
비교와 하네스 성능 비교를 분리해서 봐야 하는 이유가 여기에 있다.

## 프레임워크와의 차이

LangGraph나 Semantic Kernel 같은 프레임워크는 에이전트를 직접 만들 때 쓰는 라이브러리다.
하네스는 이미 완성된 실행 환경에 가깝고, 사용자는 작업을 지시하는 쪽에 선다.
경계가 뚜렷하지는 않으며, 플러그인 구조를 가진 하네스일수록 프레임워크에 가까워진다.

## 비교할 때 볼 항목

| 항목 | 확인할 내용 |
| --- | --- |
| 모델 종속성 | 특정 모델에 묶여 있는지, 프로바이더를 교체할 수 있는지 |
| 도구 확장 | 도구를 추가하는 방법, MCP 지원 여부 |
| 컨텍스트 관리 | 긴 작업에서 컨텍스트를 어떻게 처리하는지 |
| 격리 | 파일 시스템과 명령 실행을 어디까지 제한하는지 |
| 인터페이스 | 명령줄, 웹, 편집기 통합 중 무엇을 제공하는지 |
| 확장 지점 | 어느 부분까지 교체 가능한지 |
